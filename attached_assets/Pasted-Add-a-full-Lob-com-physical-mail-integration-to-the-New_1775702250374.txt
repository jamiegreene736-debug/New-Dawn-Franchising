Add a full Lob.com physical mail integration to the New Dawn Franchising
CRM. This covers the client card UI, the AI agent pipeline, the approval
flow, and full delivery tracking. Physical letters are NEVER sent
automatically — they are always recommended by the agent and require
Dylan's explicit approval before anything is submitted to Lob.

---

## LOB INTEGRATION OVERVIEW

Install the Lob SDK:
  npm install @lob/lob-typescript-sdk

Lob is used exclusively for sending personalised physical letters to
high-scoring leads (score 80+) who have a verified mailing address.
The agent drafts the letter content using OpenAI, prepares the letter
in the staging area, recommends it to Dylan in the daily briefing email,
and only submits it to Lob after Dylan replies with explicit approval.

## PART 2 — LETTER DRAFT GENERATION (OpenAI)

When "Draft Letter Now" is clicked on the lead record, or when the
agent automatically prepares a letter draft during the 6 AM run,
use this OpenAI prompt structure:

SYSTEM:
"You are drafting a physical letter from Dylan at New Dawn Franchising
to a prospective client. This letter will be printed on New Dawn
Franchising letterhead and physically mailed to their business address.

The letter must feel personal, warm, and handwritten in tone — not
like a marketing flyer. It is from Dylan personally, not from the
company. It should read like a thoughtful note from one business
professional to another.

Hard rules:
- Max 250 words total
- Open with Dear [firstName]
- First paragraph: acknowledge something specific about them or their
  business (use the research dossier data provided)
- Second paragraph: one or two sentences about what New Dawn Franchising
  does and why it might be relevant to them specifically
- Third paragraph: a single clear CTA — scan the QR code below to book
  a free 20-minute Zoom call with Dylan
- Close: warm sign-off as Dylan, handwritten-style
- Do NOT mention investment amounts, visa guarantees, or fees
- Do NOT use corporate jargon or buzzwords
- Do NOT mention that this letter was AI-generated
- Always end with: 'P.S. If you'd prefer to reach me directly,
  feel free to reply to this letter or email me at [Dylan's email].'"

Name: [firstName] [lastName]

## PART 4 — LOB API FUNCTIONS (backend)

Build these functions in a dedicated lob.service.ts file:

async function createLetter(lead, letterBody, dailyBatchId):
  - Validates lead has a mailing address
  - Checks Lob's supported countries list before attempting
  - Calls lob.letters.create() with:
      description: "NDF outreach letter — [lead name] — [date]"
      to: {
        name: lead.firstName + " " + lead.lastName,
        address_line1: lead.mailingAddress.line1,
        address_line2: lead.mailingAddress.line2,
        address_city: lead.mailingAddress.city,
        address_state: lead.mailingAddress.state,
        address_zip: lead.mailingAddress.zip,
        address_country: lead.mailingAddress.country
      }
      from: {
        name: "Dylan [Last Name]",
        address_line1: [NDF street address],
        address_city: [NDF city],
        address_state: [NDF state],
        address_zip: [NDF zip],
        address_country: "US"
      }
      template_id: process.env.LOB_TEMPLATE_ID
      merge_variables: {
        recipientName: ...,
        letterBody: letterBody,
        qrCodeUrl: process.env.CALENDLY_URL,
        date: today,
        ... (all template vars)
      }
      send_date: tomorrow (never same-day to allow for last-minute cancellation)
  - Returns { lobLetterId, expectedDeliveryDate, price }
  - On success: update OutreachMessage record in DB
  - On failure: log error, notify Dylan via Slack, throw error

async function getLobLetterStatus(lobLetterId):
  - Calls lob.letters.get(lobLetterId)
  - Returns current status and tracking info
  - Used by the status polling job

async function cancelLobLetter(lobLetterId):
  - Calls lob.letters.cancel(lobLetterId)
  - Only possible before the letter enters production (Lob has a window)
  - If cancellation window has passed, log it and notify Dylan
  - Update OutreachMessage status to "cancelled"

async function getEstimatedCost(country):
  - Uses Lob's pricing to return estimated cost for a given country
  - Used to show cost estimates in the UI and daily brief before approval

async function validateAddress(address):
  - Calls Lob's address verification endpoint before creating any letter
  - Returns { isValid, correctedAddress, deliverability }
  - If address is undeliverable, flag on the lead record and exclude
    from letter recommendations until address is corrected

## PART 5 — LOB STATUS WEBHOOK

Register a Lob webhook endpoint on your backend:
POST /webhooks/lob

Lob will POST to this endpoint when a letter's status changes.
Handle these events:

letter.created → update status to "submitted_to_lob"
letter.rendered_pdf → log (internal, no action needed)
letter.rendered_thumbnails → log
letter.mailed → update status to "in_transit", store mailed date
letter.in_local_area → update status to "in_local_area" (near delivery)
letter.processed_for_delivery → update status to "processed_for_delivery"
letter.re-routed → log, notify Dylan via Slack
letter.returned_to_sender → update status to "returned",
  notify Dylan via Slack: "✉️ Letter to [lead name] was returned
  to sender. Address may be incorrect. [portal link]"
letter.failed → update status to "failed",
  notify Dylan via Slack immediately

For each status change: update the OutreachMessage record, update the
Lead record's letterStatus field, add an entry to the Activity timeline
on the lead record ("Letter status updated: in_transit — Est. delivery
April 17-20").

## PART 6 — DAILY BRIEF INTEGRATION (agent updates)

During the 6 AM preparation run, the agent should:

1. Query all leads where:
   - aiScore >= 80 (or Dylan's configured threshold)
   - mailingAddress is not null
   - letterStatus = "none" (never received a letter)
   - Lead is not on the DNC list
   - Lead's country is in Lob's supported countries list

2. For each qualifying lead:
   - Call OpenAI to generate letter body
   - Call Lob address validation endpoint to verify the address
   - If address invalid: flag on lead record, exclude from brief
   - If address valid: store draft in OutreachMessage with
     status="draft_pending_approval" and include in today's batch

3. In the daily briefing email, add the "✉️ PHYSICAL MAIL
   RECOMMENDATIONS" section (see Daily Brief format below)

4. Cap letter recommendations at the configured max per day
   (default 5) to keep the brief from getting overwhelming

## IMPORTANT BUILD NOTES

- The send_date on every Lob letter should be set to the next
  business day (never same day) — this gives the cancellation
  window time to work properly
- Always run Lob address validation BEFORE including a letter
  recommendation in the daily brief — never recommend a letter
  to an undeliverable address
- If Lob API is down during the 6 AM preparation run, skip letter
  drafting for that day, note it in the brief:
  "✉️ Letter recommendations unavailable today — Lob API unreachable.
  Will retry tomorrow."
- If a lead unsubscribes or is added to DNC after a letter has been
  submitted to Lob but before the cancellation window closes:
  attempt automatic cancellation via Lob API immediately and
  log the result
- Letter cost is tracked in the DB and surfaced in analytics —
  Dylan should be able to see his monthly Lob spend at a glance
- Never hardcode Dylan's personal address as the return address —
  always use the NDF business address from env variables
- International address formatting varies by country — use a library
  like i18n-postal-address (npm) to format addresses correctly for
  each destination country before displaying in the UI and in the
  Lob template
