You are building a full CRM system to be added to the existing 
New Dawn Franchising admin portal. This is for managing immigration 
attorney and consultant contacts for E-2 visa investor outreach.

EXISTING TECH STACK (do not change):

- Database: PostgreSQL (use existing DATABASE_URL)
- Email: SendGrid (SENDGRID_API_KEY)

- Frontend: React + Tailwind CSS

- title (varchar)

- id (UUID, primary key)

  'sending', 'sent', 'paused')

- stats (jsonb — open_rate, click_rate, 
  reply_rate, bounce_rate)

TABLE: sequences
- id (UUID, primary key)

- id (UUID, primary key)

- contact_id (UUID, FK to contacts)
- current_step (integer, default 0)

  'completed', 'stopped')

TABLE: pipeline_deals
- id (UUID, primary key)
- contact_id (UUID, FK to contacts)

  'responded', 'call_scheduled', 
  'active_partner', 'closed')

- referral_value (decimal)
- moved_at (timestamp)
- created_at (timestamp)

TABLE: email_templates
- id (UUID, primary key)
- name (varchar)
- subject (varchar)
- body (text — supports merge tags)
- category (varchar)
- created_at (timestamp)

════════════════════════════════════════
PHASE 2: LEAD SCORING ENGINE
════════════════════════════════════════

Create /backend/services/leadScoring.js

Auto-calculate lead_score (0–100) whenever a 
contact is created or updated. Score based on:

+20 — Country is in high E-2 activity list:
  Mexico, Colombia, Brazil, UAE, Saudi Arabia, 
  South Korea, Taiwan, Canada, Israel, UK
+10 — Country is in medium E-2 list:
  China, India, Germany, France, Spain, Australia
+15 — persona_type is 'immigration_attorney'
+10 — persona_type is 'immigration_consultant' 
  or 'business_migration_agent'
+5  — persona_type is 'relocation_consultant' 
  or 'international_tax_advisor'
+15 — email is present and valid format
+10 — phone is present
+5  — linkedin_url is present
+10 — status is 'responded' or 'call_scheduled'
+5  — has opened at least one email 
  (check contact_activities)
-10 — status is 'bounced' or 'unsubscribed'

Cap score at 100. Store result in contacts.lead_score.
Run this function whenever contact is saved.
Expose as POST /api/contacts/:id/rescore

════════════════════════════════════════
PHASE 3: APOLLO API INTEGRATION
════════════════════════════════════════

Create /backend/services/apolloService.js

Use environment variable: APOLLO_API_KEY

Implement the following Apollo.io API calls:

1. PEOPLE SEARCH
   POST https://api.apollo.io/v1/mixed_people/search
   Headers: { 'Content-Type': 'application/json',
              'X-Api-Key': process.env.APOLLO_API_KEY }
   Body params:
   - person_titles: array of job titles
   - person_locations: array of countries/cities
   - q_keywords: search keywords
   - page: pagination
   - per_page: 25
   
2. EMAIL ENRICHMENT
   POST https://api.apollo.io/v1/people/match
   Match by: name + company domain
   Returns verified email address

3. BULK IMPORT
   After Apollo search returns results, auto-map 
   each result to the contacts schema:
   - Run deduplication check against existing emails
   - Calculate lead score immediately
   - Set source = "Apollo"
   - Log import count and skip count

Expose as:
POST /api/apollo/search — trigger search + import
GET  /api/apollo/status — last run stats

PHASE 6: DUPLICATE DETECTION & MERGE
════════════════════════════════════════

On every new contact import or manual add:
1. Check for exact email match → block as duplicate
2. Check for fuzzy name + firm match 
   (>85% similarity using string-similarity library)
   → flag as "possible duplicate" with yellow banner
3. /contacts/duplicates page shows all flagged pairs
4. "Merge" button on each pair:
   - Keep the contact with more activity history
   - Merge all activities, tags, tasks onto survivor
   - Delete the duplicate record
